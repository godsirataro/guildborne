# Permanent plot and theme ownership

Land plots and purchased building themes are permanent one-time rights. Their existing `productId` / `ProductId` fields now represent **Game Pass IDs**, distinct from Elixir's repeatable Developer Product ID. All IDs remain zero and `Runtime.PermanentPassesEnabled` remains false. No sale, prompt, cloud purchase or paid entitlement was created.

Roblox distinguishes one-time [passes](https://create.roblox.com/docs/production/monetization/passes) from repeatable [developer products](https://create.roblox.com/docs/production/monetization/developer-products). The staged restore adapter checks `UserOwnsGamePassAsync` on join and rechecks ownership after the server purchase-finished event; see [MarketplaceService](https://create.roblox.com/docs/reference/engine/classes/MarketplaceService). Existing Elixir `ProcessReceipt` remains the sole developer-product receipt handler.

`PermanentPassCatalog` excludes zero IDs and rejects duplicate IDs across land and themes. The private `CommitPermanentPass` uses the existing lease, revision, durable candidate, audit and uncertain-write recovery transaction. Stable entitlement references outlive the recent command replay window. Repeated restoration does not create rewards, debit materials, change quests or reopen land. Existing purchase references remain private in profile projections.

The injected coordinator fails closed on ownership errors/nonboolean responses, serializes concurrent restores and checks session identity after yielding ownership/refresh operations. It does not revoke previously saved rights when an ownership check returns false. Runtime retries transient restore failures three times while the same player/session remains present; pending durable saves also recover via the existing heartbeat. A platform outage after those retries requires a later rejoin. Presentation/audit notification failures do not roll back a saved right.

Paid rights acquired outside the in-game offer are retained even before quest completion. Quest milestones, required materials and the explicit open action still gate buildable land. This follows the user's quest → purchase → materials → open journey for in-game offers without discarding externally acquired ownership.

The in-game offer now has EN/TH land and theme buttons, with an explicit reminder that land still needs materials. The client sends only a kind/key; it cannot set a pass ID, price or purchased state. Server prompt admission requires the owner's safe guild area, active saved profile, matching revision and a healthy lease. Land needs an explicitly unlocked quest milestone. The same checks run again after the platform ownership query yields. Already-owned passes restore instead of prompting; one dialog can be open at a time, with a three-second reopening cooldown. The Roblox dialog supplies the current price and final confirmation. Cancellation grants nothing and releases the dialog lock.

Still required before sales: finalized pass configuration, persistent staging ownership/rejoin acceptance with real platform IDs, actual Roblox dialog/cancellation/outage acceptance and human/mobile/controller review. Current projected `purchaseAvailable` remains false because the feature and IDs are disabled. This is a disabled fulfillment and offer implementation, not a completed paid customer journey.
