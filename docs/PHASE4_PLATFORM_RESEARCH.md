# Phase 4 official platform verification

Verified 2026-09-29 against current Roblox Creator Hub documentation. These are platform limits, not throughput promised by Guildborne.

- [Data stores](https://create.roblox.com/docs/cloud-services/data-stores): storage is shared across servers in one experience. Studio API access can reach the same durable data; use a staging universe and isolated names. UpdateAsync callbacks can rerun and must not yield or perform external side effects.
- [DataStore limits](https://create.roblox.com/docs/cloud-services/data-stores/error-codes-and-limits): UpdateAsync consumes read and write budgets. Current experience standard read/write rates are 300 + 40 × concurrent users / 300 + 20 × concurrent users per minute. Default server read/write rates are each 60 + 40 × local players. Entries allow 4,194,304 characters, names/keys/scopes 50. Per-key read/write throughput is 25/4 MB per minute, rounded up per KB. Studio Run limits can differ. Guildborne checks live budget, applies bounded retries, caches reads, caps a pilot book at 1 MiB, and stops admission at 128 lifetime tickets well before that byte limit. The cap is not a claim that a 1 MiB hot key can sustain high traffic.
- [Memory stores](https://create.roblox.com/docs/cloud-services/memory-stores): transient, expiry-based; quota is 64 KB + 1.2 KB per user and 1000 + 120 × concurrent users request units/minute. A single value is limited to 32 KB. Studio transient data is isolated from production, but can have low quotas and elevated latency. No economic ownership lives here.
- [Sorted maps](https://create.roblox.com/docs/cloud-services/memory-stores/sorted-map): ordered lookup and atomic key update support disposable book-depth snapshots. Guildborne shards by namespace, item and side, explicitly expires snapshots after 90 seconds, bounds each to 20 rows, and rejects older projected revisions. Recovery republishes durable books.
- [Hash maps](https://create.roblox.com/docs/cloud-services/memory-stores/hash-map): unordered, automatically partitioned, useful for large key spaces. Not needed for this five-item pilot. Maximum TTL is 3,888,000 seconds; the application intentionally uses a much shorter TTL. No MemoryStoreQueue is used or required for recovery.
- [MessagingService](https://create.roblox.com/docs/reference/engine/classes/MessagingService): best-effort delivery, 1 KB messages; current send budget 600 + 240 × local players/minute, receive per topic 40 + 80 × servers/minute. Guildborne sends item/revision invalidations, coalesces changes for two seconds, and retains a ten-second read-cache TTL so missing notifications cannot strand visibility or authorize stale fills.
- [StudioTestService](https://create.roblox.com/docs/reference/engine/classes/StudioTestService): one multiplayer test per Studio instance, up to eight clients on one server. Two/four clients in these tests do not establish independent production-server behavior.

Correctness uses atomic single-item-book compare/update, not a MemoryStore lease. Expired or missing coordination cannot create a second fill. Neither multi-key transactions nor guaranteed message delivery is assumed. See the [implementation](PHASE4_IMPLEMENTATION.md) for the bounded pilot and its public-release gates.
