# Modular character pipeline

Runtime and Blender exchange exact original asset IDs from the reviewed intake.
`tools/build_appearance_catalog.py` generates the runtime catalog deterministically.
Do not rerun the original workbook generator over production status. Catalog
targets are distinct from the observed source/export/import register.

Start with `CHR_BDY_HUMAN_STANDARD_V01` and `CHR_BDY_HUMAN_HEAVY_V01`. Bodies contain
the 15 named `*_Geo` core objects from the contract, plus an invisible rig/root.
Hair, clothing and hats stay removable. The base rendering path retains opaque
modesty independently of outfit slots. Wizard uses Human geometry and attire.

The existing hero rig remains the gameplay proxy. The private candidate overlays
15 labeled Parts on existing R15 segments or existing R6 hero limbs. R6 companions
do not gain independently animated elbows/knees from an overlay. These placeholders
are not imported MeshParts or final character art. Collider, speed, reach and
server stat calculation remain unchanged. Source geometry and real import must
replace the test substitute before accepting the golden path.

Blender production owns geometry, caps, UVs, weights, attachments and export.
Roblox integration owns imported model identity, R15 assembly, actual WrapLayer/
WrapTarget data and per-preset fitting. An export is not an import. Cages are not
generated by relabeling rigid blocks. No universal-fit claim is made.

Official requirements were checked on 2026-10-10: [body specifications](https://create.roblox.com/docs/avatar/character-bodies/specifications),
[layered accessories](https://create.roblox.com/docs/avatar/layered-accessories),
and [character appearance](https://create.roblox.com/docs/characters/appearance).
The body documentation requires 15 separate named meshes and watertight caps.
Use actual import axes, rig settings and attachment transforms rather than treating
generic Blender export settings as tested Studio compatibility.

Build a cloud-free candidate with `tools/build_character_preview.ps1`. It writes
only generated build output and uses the existing offline Memory configuration,
whose universe allowlist is empty. Never save/publish this over staging. Human
Standard/Heavy acceptance precedes expansion to the remaining races.

Local production on 2026-10-11 produced seven original `.blend` sources and
their FBX/GLB exports. Body audits and body roundtrips passed. Exact evaluated
geometry is retained in `GeneratedGeometry.luau` with source hashes.
`LocalGeometryPreview` creates isolated static EditableMesh MeshParts without
uploading or attaching to actors. It never registers an asset ID or substitutes
for R15/cage acceptance. Its mesh resource cleanup was checked in Studio.

`BuildRig(selection)` is a separate isolated source-derived articulation path.
It uses the actual Blender bind frames for 15 Motor6Ds, joint/source attachments
and a separate invisible anchored root. Fixed-size EditableMeshes retain the
exact geometry while avoiding the client allocation failure observed with many
dynamic meshes. Hair/headwear use real rigid attachment welds. Flexible garments
are omitted with `UNAVAILABLE_UNSKINNED_NO_CAGES`; this path never treats them as
rigid clothing. Both bodies played a temporary local joint-sweep clip in Studio,
with 13 moving joints each. This is rig/clip integration, not accepted gameplay
animation, foot contact, garment fit or production import. Source forward maps
to Roblox +Z; native animation retargeting/orientation remains a separate check.

## Shared world NPC appearance

The user confirmed on 2026-10-11 that this foundation must also create world NPCs.
Player, Hero and NPC appearance share the original asset IDs, body presets,
palettes, skeleton/attachments and per-preset clothing approvals. NPC role,
dialogue, schedules, quest ownership and rewards remain in the existing world
systems. NPC design-owned clothing is not a player inventory entitlement;
`CommitAppearance` remains restricted to the player's owned actors. Cosmetic
race or skin never determines an NPC's personality, profession or stats.

Current `CentralCityWorld` creates eight role NPCs through `HeroRig.Build` and
`CityNpcAppearance`. Their R6 proxies can receive the current placeholder
overlay. The shared renderer preserves `CityRoleVisual` along with equipped
items, retaining profession props and their original welds. No world spawn is
automatically migrated by this change.

The separate civic cast built by `CityCharacterKit` and `FriendlyNpcKit` uses a
nested `Skeleton.Root` and bone-to-geometry offsets. It needs an explicit shared
renderer adapter; current application rejects it before mutation with
`RIG_ROOT_MISSING`. Do not rename or rebuild these roots/joints: existing
`FriendlyNpcAnimator`, labels, `DesignId`/`NpcId`, prompt callbacks, tags, escort
and cleanup depend on them. The first Human adapter candidates are
`marshal_elian`, `cartographer_nyra` and `harbormaster_sela`.

Finish the real Human Standard/Heavy outfit gate before enabling world NPC
migration or other races. NPC acceptance then requires real work-tool/hand
contact, talk interruption/resume, respawn and streaming/unload cleanup, plus
quest transactions and busy-scene performance. A builder fixture does not pass
these world journeys.
