# Local shared travel adapter

Status: SOURCE IMPLEMENTED / RULE TESTED / ADAPTER STUDIO ACCEPTANCE PENDING.

The existing TravelService accepts an optional fourth server-only descriptor: Session, Gate, Entry (Part or per-player resolver), Exit, Geometry, Landing, Fallback, Contains and optional Spawn. Methods EnterLocal, ReturnLocal and IsLocal expose individual consented entry/return. No production destination, settlement allowlist or client protocol changed. World/Bootstrap bindings belong to the integrating coordinator.

Entry retains normal readiness, downed, combat, tower, range and cooldown checks plus injected novice/mentor authorization. Return stores exact session object, epoch/token, character, original transform, zone, respawn and city return stop. Repeated entry cannot overwrite it. Safe geometry is checked before movement; blocked original return uses the ordinary destination fallback. Death/respawn/fall recovery uses the same connection snapshot; removal clears transient state. Original travel works with descriptor omitted. No automatic Party convoy or reservation is implemented.

Rule cases cover active/busy/session/character identity, novice/mentor/downed/combat/tower refusal, distant/NaN prompt distance, repeated entry and legacy rules/cooldown. Adapter cases cover actual enter/return snapshots, blocked landings, refusal, fall, connection replacement, remove, omitted-descriptor ordinary travel, return fallback, respawn and closed-entry/safe-exit behavior. The fifth factory argument is trusted platform dependency injection; normal callers omit it. Gate receives `(player, entering)` so scene closure can reject entry without rejecting exit.

These tests do not validate actual Roblox raycasts, native prompt input, engine character respawn ordering or multiplayer travel. Those remain required integration checks, along with independent source review. No claim of full six-player convoy or Public readiness follows.
