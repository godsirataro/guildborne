# Slice validation

Phase 2.1 adds 19 combat scenarios to the previous 40, plus `studio_combat_probe.luau` (Server observation only). Run the sampler with five selected heroes, walk into the Goblin Camp, then return to the hub and wait for saves/recovery. It observes basic attacks, abilities, damage, healing, taunt, deaths/rewards and server network ownership. See [actual Studio evidence and persistence procedure](../docs/PHASE2_1_STUDIO_TEST.md). Do not mistake Memory rejoin for a real DataStore test.

Phase 1.6 adds `studio_heroes_probe.luau`. Run after the baseline probe in the same fresh Memory or isolated QA DataStore session. It earns optional recruitment Gold through real repeat quests, equips all five classes, verifies selected/resting/away/returned models, rejects oversized and duplicate parties, and leaves a five-member Thai party. Never run these probes against an existing user's profile. Invalid protocol packets intentionally return no request ID; the observer recognizes that rejection without changing the server contract. Inspect `_G.GBBaselineDone` / `_G.GBBaselineError` and `_G.GBHeroesDone` / `_G.GBHeroesError` for completion. Real persistence requires Stop/Play and comparison of the complete saved revision/data, including an active five-member snapshot; Memory is insufficient. See [Phase 1.6 evidence](../docs/PHASE1_6_IMPLEMENTATION.md).

Art Phase 1.5 adds `studio_art_probe.luau`: run it in the Studio **Server** context after a player joins, once at Hall 1 and again after the actual Hall upgrade. It checks asset count, script/collision/effect discipline, bilingual prompts, part budget and nine unobstructed route sweeps. It never changes player data. Run the existing native gameplay probe separately in a fresh Memory session, then restore Runtime to DataStore and use the persistence probe for real rejoin. Art evidence is in [the Phase 1.5 report](../docs/PHASE1_5_IMPLEMENTATION.md).

Run `.\tools\setup_tools.ps1` once, then `.\tools\validate.ps1` from the repository. The suite runs 59 standalone Luau scenarios, Rojo build/source map, Roblox-aware strict analysis, compilation, JSON/TOML and local document-link checks, built-place boundary checks and whitespace checks. To run domain tests alone: `.\.tools\luau\luau.exe tests/run.luau`.

The test runner injects time and persistence into the actual domain modules and PlayerDataService. Scenarios cover conservation, full-inventory rollback, replay/early/forged claims, migration, lease fencing, lost responses, crash/rejoin, shutdown, audit export and provider failure. A 400-step deterministic adversarial sequence checks schema/Gold invariants after every step. Tests stay outside the Rojo runtime tree; no test framework ships to clients or servers.

The injected store is not Roblox DataStoreService. Real backend quotas/concurrency and persistent rejoin still need staging. For native client/server testing, paste the complete contents of `tests/studio_client_probe.luau` into Studio's **client** Command Bar in a fresh memory Play session, then click Run. It uses actual RemoteEvents, waits for real quest deadlines, asserts replay/rejection behavior and the final 10-Gold Hall-2 state. Do not run it against an existing progressed profile. It is outside the shipped tree. See the [14 manual tests](../docs/PHASE1_STUDIO_TEST.md), [security](../docs/SECURITY.md) and [roadmap](../docs/ROADMAP.md) for remaining acceptance gates. Phase 2.1 combat is covered by the separate sampler and report above; Phase 2.2 and 2.3 now have separate reports below.

`studio_persistence_probe.luau` is a separate manual staging probe, restricted to the verified universe/place, a positive account ID and Active Persistent mode. Prefix the pasted file with `_G.GBPersistenceStage = "prepare";` for an unused profile; it checkpoints Thai, tutorial, Warrior, party and an active Trail Watch. Capture `GBPERSIST CHECKPOINT`, Stop/Play, then run stage `inspect` and compare its entire `{revision, data}` to that checkpoint. Stage `finish` resumes that first quest, completes the remaining loop with duplicate-claim assertions, upgrades Hall and saves English. Stop/Play and inspect/compare again. Stage `thai` restores Thai afterward if desired. Each stage uses only public commands; it never resets profiles or writes DataStores directly. Keep snapshots as evidence. A Studio Stop/Play backend test still does not certify a published Roblox Player session or live crash/concurrency behavior.
